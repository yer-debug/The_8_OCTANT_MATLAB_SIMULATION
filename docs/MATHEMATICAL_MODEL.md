# Mathematical Model

## Coordinates and octants

A position is represented by $\mathbf{r} = [x, y, z]$. Open octants are
classified by coordinate signs using this convention:

| Octant | Sign of (x, y, z) |
| --- | --- |
| I | (+, +, +) |
| II | (-, +, +) |
| III | (-, -, +) |
| IV | (+, -, +) |
| V | (+, +, -) |
| VI | (-, +, -) |
| VII | (-, -, -) |
| VIII | (+, -, -) |

If any coordinate is zero, the point belongs to a coordinate plane, axis, or
the origin and is reported as `Boundary`.

## Vector quantities

For $\mathbf{v} = [v_x, v_y, v_z]$, magnitude is
$\lVert\mathbf{v}\rVert = \sqrt{v_x^2 + v_y^2 + v_z^2}$. The direction angles
with the positive coordinate axes are
$[\cos^{-1}(v_x/\lVert\mathbf{v}\rVert),
\cos^{-1}(v_y/\lVert\mathbf{v}\rVert),
\cos^{-1}(v_z/\lVert\mathbf{v}\rVert)]$, converted to degrees. These angles
are undefined for the zero vector.

For the example $[-3, 4, 5]$, magnitude is $\sqrt{50}$ and signs are
$(-, +, +)$, which identifies Octant II.

The vector engine supports component-wise addition and subtraction, scalar
multiplication, dot product, and cross product. The unit vector is
$\hat{\mathbf{v}} = \mathbf{v}/\lVert\mathbf{v}\rVert$ when the magnitude is
nonzero. The angle between nonzero vectors is
$\cos^{-1}((\mathbf{a}\cdot\mathbf{b})/(\lVert\mathbf{a}\rVert
\lVert\mathbf{b}\rVert))$, in degrees; its cosine is clamped to $[-1, 1]$
before evaluation to account for floating-point roundoff.

Parallel and perpendicular checks use a default relative tolerance of
$10^{-10}$. Perpendicularity tests
$|\mathbf{a}\cdot\mathbf{b}| \leq \tau\lVert\mathbf{a}\rVert
\lVert\mathbf{b}\rVert$; parallelism tests
$\lVert\mathbf{a}\times\mathbf{b}\rVert \leq
	au\lVert\mathbf{a}\rVert\lVert\mathbf{b}\rVert$. An optional nonnegative
tolerance can be provided. Zero vectors are neither classified as parallel
nor perpendicular. A zero vector has no unit vector or direction angles, and
the angle between vectors is undefined if either input is zero; these methods
return NaN direction angles or raise a `zeroVector` error, respectively.

## Motion Model

The visualization includes eight satellites initialized one per open octant.
Their illustrative motion is defined component-wise from initial position
$\mathbf{r}_0$, configured amplitude vector $\mathbf{A}$, angular frequency
$\omega$, and simulation time $t$:

$$
\mathbf{r}(t) = \mathbf{r}_0\cos(\omega t) + \mathbf{A}\sin(\omega t)
$$

The displayed velocity is the analytic derivative:

$$
\mathbf{v}(t) = \omega[-\mathbf{r}_0\sin(\omega t) +
\mathbf{A}\cos(\omega t)]
$$

Trails show samples from the recent configured time window and terminate at
the current position. This periodic kinematic model is intended to demonstrate
position, velocity, and octant transitions. It is not an orbital mechanics
model: no forces, gravity, or perturbations are calculated.

## Electromagnetic fields

Satellite coordinates and kinematics are displayed in kilometres. Field
calculations convert positions to metres at the field-engine boundary. Charge
is specified in coulombs, current in amperes, electric field in N/C, and
magnetic flux density in teslas.

For a point charge $q$ at the origin, the electric field is

$$
\mathbf{E}(\mathbf{r}) = \frac{1}{4\pi\epsilon_0}
\frac{q\mathbf{r}}{\lVert\mathbf{r}\rVert^3},
\qquad \mathbf{r}\ne\mathbf{0}
$$

For an ideal infinite wire carrying current $I$ in the positive Z direction,
the magnetic field at perpendicular displacement $(x,y)$ from the wire is

$$
\mathbf{B}(x,y) = \frac{\mu_0 I}{2\pi(x^2+y^2)}[-y, x, 0],
\qquad x^2+y^2 > 0
$$

The electric model is singular at the point charge. The magnetic model is
singular on the wire axis. Both return an undefined flag and NaN components at
their singularity; the visualizer omits arrows at those locations. Field arrow
length is normalized for legibility, so it does not encode field magnitude;
the inspector reports the numerical SI magnitude.

These source configurations are teaching examples, not a model of fields
generated by the displayed satellites. No fields from moving charges, finite
conductors, material responses, or boundary conditions are included.

## Validation Scope

Automated tests check octant and boundary classification, vector operations,
motion equations and derivatives, trajectory sampling, clock stepping and
reset, field directions and singularities, and representative UI/graphics
controls. They do not establish physical accuracy beyond the stated analytic
equations and assumptions. Run `run_validation` in MATLAB to execute the suite
and Code Analyzer from the project root or any working folder.
